# Downloader compatibility

## Boundary

Yoink runs one Telegram bot with optional functional modules. Personal cookies belong to a user, not to a module. The global cookie pool is a separate credential source and requires enabled, authorized use. Runtime bot identifiers bind Telegram routing and receipts to the configured account, not to separate module bots.

The Rust Telegram adapter remains experimental and opt-in. Trusted private messages register missing users under the shared open/approved-only policy when a native database is configured. Authorized ordinary users can use caller-owned media commands, supported non-secret overrides, private settings/format/subtitle controls, durable quality and clip dialogs, visible URLs and scoped job/cancel operations. Personal cookie controls and proxy-use toggles require authorized caller-private scope. Shared credential management and system configuration remain separate administrative workflows. A separate `YOINK_RUST_TELEGRAM_GROUPS_ENABLED=true` setting enables media commands for known, authorized users in registered groups and topics. Production Python services and PostgreSQL data are unchanged. Engine support, a Telegram command, and verified end-to-end behavior are separate milestones.

The existing [media fixture](../../backend/scripts/test-media.mjs) already exercises real container processing, native video delivery, crash/retry/cancellation handling, file-ID cache reuse and recovery, versioned cookies/proxies, revocation and credential redaction. A bounded private settings editor covers supported format and subtitle preferences. `/lang` selects the saved interface language. Bare `/subs` edits standalone-subtitle language and automatic-subtitle preferences. Other legacy settings workflows remain unported.

## Quotas and active work

Newly admitted operations consume user-wide minute/hour/day quotas, defaulting to 5/30/100. Each window starts at its first accepted operation and resets independently after 60/3600/86400 seconds. The existing imported `rate_limits` rows remain authoritative; restart does not reset them. Actor scope spans bots, chats, topics and media modes. Only the exact configured owner ID bypasses time quotas. A stored owner/admin role or a local group grant does not grant this exemption.

Charging commits in the same transaction as the new operation. Replay and conflicts are resolved before charging, including completed-operation replay after restart. Invalid, unauthorized, over-capacity and quota-refused requests do not consume counters. Worker retries do not consume another quota unit. A new accepted operation consumes one unit even if it later fails or uses cached media. Quota errors report a rounded-up wait sufficient for every exhausted window, without exposing the source. Telegram renders the wait in the saved EN/RU interface language.

A separate per-actor active-work limit defaults to three operations across `running` and `delivering`, including cached sends. It applies to the configured owner too. Claiming checks the durable operation state atomically; busy actors remain queued while other actors can proceed. Retry, cancellation, terminal outcomes and expired-lease recovery release active capacity through the existing state transitions. Pending-queue limits remain separate admission guards, not time quotas or active slots.

`YOINK_RUST_DOWNLOAD_QUOTA_MINUTE`, `YOINK_RUST_DOWNLOAD_QUOTA_HOUR` and `YOINK_RUST_DOWNLOAD_QUOTA_DAY` accept 1 through 1000000. `YOINK_RUST_DOWNLOAD_MAX_ACTIVE_PER_USER` accepts 1 through 100. Migration v15 adds the active-actor index without replacing imported counters. Older runtimes reject this schema; rollback requires a compatible binary or a pre-migration backup. No production migration or configuration change runs during verification.

`just test-media quotas` exercises quota admission, cache hits, replay, restart, independent window reset, imported counters, authorization and localized refusals against the fixture Bot API and real container worker. Native storage regressions cover exact reset boundaries, concurrent last-unit admission and active-slot claims, including cross-bot actor scope.

## Command contract

- `/download URL` retains its single-video grammar and does not accept flags. It now inherits saved video settings at admission.
- `/video URL`, `/audio URL` and `/image URL` select video, audio and gallery-image modes.
- `/subs URL` sends standalone SRT/VTT documents, falling back to ASS/SSA, without downloading video. It accepts only `--subtitle-language CODE` and `--subtitle-auto true|false`. Bare `/subs` opens a private menu for standalone-subtitle language and automatic-subtitle preferences. This command does not embed or burn subtitles into video.
- `/playlist URL` requests entries 1 through 20. `/playlist N URL` requests 1 through N. `/audio N URL` and `/video N URL` request only entry N. Explicit `A-B` preserves order, and `-N` selects the final N entries. A range before the URL is always a playlist selector, even when the URL has a `t`/`start` query parameter. Domain/protocol ranges are bounded to 100 entries, while configured worker item/byte budgets may be tighter.
- `/cut URL START END` remains an immediate request. `/cut URL` and `/cut URL START` instead open the private interactive clip dialog. Unsigned decimal seconds and colon-form times are accepted. A numeric END smaller than START is a duration, otherwise it is absolute. A colon-form END is always absolute. For `/video` and `/audio`, trailing `URL START DURATION` or `URL?t=START DURATION` arguments instead use numeric durations. Parser tests and EN/RU help distinguish these forms.
- Unknown or malformed arguments must not create operations. Source URLs and credential-bearing query values stay out of debug output and error replies.

## Plain URL messages

A visible Telegram `url` entity submits a video through the same authorization, saved preferences, progress, cache and message-based idempotency path as `/video`. Text before the URL may contain Unicode, including emoji. Entity ranges use UTF-16 code units and must land on character boundaries. The adapter never interprets a hidden `text_link` target as a download. It ignores captions, missing URL entities, command messages and content inserted via another bot. Multiple URL entities, malformed ranges, credentials in URLs and unsupported trailing arguments produce fixed localized guidance without admission or source echo.

A trailing `START DURATION` or `START END_TIME` clips the video. Numeric durations are added to the start, while colon times are absolute. A single trailing time requires a unique valid `t` or `start` query marker. Two explicit times override a valid URL timestamp. A timestamp without trailing times opens the durable private end-time dialog, which requires summary confirmation and follows the interactive end-value rules below. Groups must supply a complete clip or use an explicit command. Active `/cut` input keeps precedence over plain URL handling. Use `/cancel` before starting an unrelated implicit download during a clip dialog.

Ordinary authorized users can submit a plain private video URL. Clip suffixes, timestamp dialogs and quality menus use the same authorized caller-private scope. In opted-in groups, a plain URL must reply to this bot or originate through this bot's inline mode, and normal user/group/topic authorization still applies. Ordinary group links are silent. Replies, uploads and cached sends stay in the incoming chat/topic with the original message reference. The native downloader also supports [inline YouTube lookup](../../backend/docs/inline-search.md). Text-only cards insert canonical watch URLs. Selection remains an actual message subject to the same destination checks.

Music-provider domains used by the legacy Music plugin are reserved for that module, including their subdomains. They do not trigger implicit video downloads. Gallery selection still needs `/image`. Saved quality `ask` opens the private per-download chooser for a ready video request, with height limits, Audio and Cut for single-video requests. Groups still require an explicit height or a concrete saved quality. Unlike the legacy thirty-second age cutoff, message age does not discard durable replay. Hidden-link extraction, music resolution, automatic message deletion and private redirection are not part of this path.

## Source format reports

Authorized actor-private `/list URL` admits a metadata-only request through the durable job queue and returns `formats.txt` as a document. It accepts exactly one HTTP(S) URL, with no flags or embedded credentials. It does not open the saved `ask` menu or apply saved codec, container or subtitle preferences. Network selection still freezes the configured personal cookie and proxy references, and execution and delivery recheck authorization and credential versions. Settings remain unchanged. Groups and direct HTTP format-report admission remain outside this command boundary.

The guarded yt-dlp probe reads provider metadata and manifests without running media downloads or postprocessors. Direct media can be identified from response headers, with unknown dimensions and codecs retained as placeholders. Playlists, live sources and sources with no supported non-DRM media candidates fail without delivery. The report uses a fixed TSV schema with at most 100 rows and a 64 KiB ceiling. It includes bounded numeric IDs, dimensions and frame rates, plus allowlisted extension, codec and protocol names. URLs, titles, headers, cookies, proxy addresses, raw metadata strings and arbitrary source format selectors are absent. The executor validates the whole report independently before opening Telegram delivery.

Same-message replay reuses the durable operation, including after restart. A new message performs a fresh metadata probe. Reports neither consult nor populate the media cache. `/list` does not change the per-download chooser or select a listed source format for a later download. Runtime and worker revisions must match. There is no schema migration, but older binaries cannot decode persisted `formats` requests, including completed jobs. Draining the queue does not restore history compatibility. Rollback needs a compatible runtime and worker or a pre-feature database backup.

`just test-media formats` runs the synthetic Bot API acceptance scenario. It checks HLS format discovery without segment requests, direct-media header discovery without a body, cookie/proxy selection, private authorization, revocation during probing, replay and restart, redaction, cache isolation and failed probes. These fixtures do not establish live external-provider compatibility.

## Per-download quality choice

For ready actor-private video requests, saved `quality=ask` opens a per-download menu unless `--height` is explicit. This applies to `/download`, `/video`, `/playlist`, immediate clip requests and visible plain URLs. Choose Best, a maximum height of 2160, 1440, 1080, 720, 480, 360, 240 or 144, or Audio. Eligible single-video requests also offer Cut. These are limits passed to the existing worker selector, not a claim that the source offers those formats. The menu does not probe metadata or contact the source. `/quality` resumes it after restart or a lost reply. Cancel uses the menu's own button. Bare `/cancel` remains a clip-dialog command.

The original URL, request mode, clip/range, explicit overrides and reply destination persist in a private draft. Choosing a height or Audio changes only that request, not the saved `ask` setting. Audio preserves the original clip, playlist selection and reply destination, switches to audio mode and resolves the current saved audio codec and file-delivery preference. Explicit `--audio-codec` and `--send-as-file` still override them. Video-only codec/container overrides are discarded for this action, and saved video preferences do not affect audio admission. Other saved format preferences and credentials are resolved when the request is admitted. Already admitted requests keep their frozen settings. A new prompt replaces a pending choice, and old buttons cannot act on the replacement. Original-message replay and changed-intent conflicts are checked before consulting current saved quality, so changing settings cannot turn a stale prompt into an implicit download.

Cut appears only for video requests without a playlist range or clip list. An immediate single `clip_range` remains eligible and seeds the editor. It transfers the original request into the clip editor without creating an operation or contacting the source. The editor can add more ranges before confirmation. The handoff and the chooser's linked `Cutting` state commit in one transaction. The editor retains the source, engine, explicit overrides and original reply destination. An existing clip seeds its start/end summary, otherwise the editor asks for a start time. Saved preferences still resolve at final admission. After transfer, the original quality menu can only resume that editor. Its old Audio, height and cancel buttons cannot start the full source. Replaying Cut after restart returns the same linked draft, including its terminal state. Replaced drafts cannot be resurrected. An unrelated active clip or a newer clip watermark blocks the transfer without changing either draft. The menu hides Cut while an older clip is active and asks the user to finish or cancel it. A newer or equal watermark requires a new URL request. A replaced linked editor shows the same guidance without an unusable resume button. Playlists and existing multi-clip requests retain Audio and height choices, but cannot enter the editor through a forged callback.

Selection is persisted before admission. Once confirmation begins, a different choice, cancellation or replacement is rejected because admission might already have succeeded. Retry the same choice to recover. Its idempotency key uses the original Telegram message, not the callback delivery. Recovery after a crash between admission and recording its result reuses the same operation. Callbacks require an accessible current-bot message in the caller's private chat and fresh authorization including bans. Menus and errors never echo source URLs.

Migration v9 adds the draft table. Migration v11 allows a durable Audio choice. Migration v12 links quality drafts to clip editors and stores the transferred request intent. Both migrations preserve existing draft rows and their revisions. Older binaries reject the new schema, so rollback requires a compatible binary or a pre-migration backup. No production migration runs as part of verification. Group behavior, explicit heights, non-video modes and direct HTTP admission remain unchanged. Interactive `/cut` uses its own durable height-choice state and original clip-session admission key. Resume that dialog with `/cut`, not `/quality`. Audio is available only in `/quality`'s per-download chooser. The separate interactive `/cut` height picker remains video-only. Provider metadata and source-aware quality lists remain unported.

`just test-media quality` runs the dedicated acceptance scenario against rebuilt images. It exercises served EN/RU Audio buttons, private authorization and bans, saved MP3 preferences, explicit clipped AAC document delivery despite invalid saved video settings, unchanged preferences, exclusive choice and crash/restart replay without another operation or upload. `just test-media quality-cut` covers the linked editor, no-admission handoff, restart/replay, stale choices, authorization, original request intent and actual clipped delivery.

## Subtitle preferences

Authorized actor-private bare `/subs` opens a dedicated menu for standalone subtitle documents. Language choices include the legacy EN/RU/ZH/JA/AR/HI/DE/FR/ES/PT presets and `zh-Hans`. Custom valid tags saved through `/settings subs_lang CODE` remain visible. The automatic-subtitle setting controls whether extraction may use automatic tracks. The menu does not claim tracks exist for a particular source and performs no extraction or media admission.

Buttons change only `subs_lang` or `subs_auto` and the shared settings revision. Authorization and bans are rechecked, and callbacks require an accessible message from this bot in the caller's private chat. Stale, replayed, malformed and old unversioned callbacks cannot mutate preferences. Changes through `/settings` or `/proxy` can invalidate `/subs` buttons, and subtitle choices can invalidate their buttons. Reopen `/subs` to recover from stale buttons or an unacknowledged Telegram edit.

The menu uses the saved interface language independently of the selected subtitle language. `/subs URL` continues to inherit these preferences unless explicit subtitle flags override them. Existing admitted jobs keep their frozen subtitle options. No enable/disable control for embedding is exposed, and `subs_enabled` remains unchanged. Standalone subtitle requests still work when that legacy embedding preference is disabled. Group download permissions are unchanged, but groups cannot use this settings menu. No schema migration is required.

`just test-media subtitle-settings` runs the dedicated acceptance scenario against rebuilt images.

## Interface language

Authorized private `/lang` opens English and Russian choices for ordinary users and the configured owner. It changes the existing user's `language` and `updated_at` fields only, without creating a user or altering roles, grants, downloader preferences, cookies, jobs or cached media. Callbacks require an accessible message from this bot in the sender's own private chat. Current role and ban checks run again in the write transaction. Pending and banned users cannot change the language. Callbacks can change only the sender's own private-chat preferences. Each accepted choice, including the current language, advances a monotonic revision. Older buttons cannot overwrite a later choice, including after restart or a switch back to the original language.

New command replies and callback responses prefer a supported saved `users.language` over Telegram's `language_code`. Missing or unsupported saved values fall back to Telegram metadata, then English. A failed locale lookup also falls back without exposing database errors or changing access decisions. Successful selection updates the menu text in the new language and removes its keyboard. Already-created progress messages retain their stored language, while new admissions use the current choice. Groups cannot change the preference through `/lang`, and existing group authorization is unchanged.

`just test-media language` runs the focused Bot API acceptance scenario, including ordinary-user selection, cross-user isolation, role/ban revocation and restart replay. No schema migration or production configuration change is required.

## Interactive clips

Authorized actor-private `/cut URL` asks for the start time, then the end time. `/cut URL START` skips the first question. Unsigned decimal seconds and colon times use the same parser as inline clips. In the interactive end prompt, a numeric value less than or equal to the start is a duration. A colon time is always absolute and must exceed the start. The immediate inline form retains its existing strictly-less-than duration rule. Direct interactive forms do not accept format flags and use saved preferences at confirmation. Editors entered through the quality menu's Cut action retain the original request's explicit format overrides.

The summary lists committed ranges in their delivery order and offers Download, Add, numbered Change/Delete controls and Cancel. Up to 20 ranges are allowed, and Add is hidden at the limit. Adding or changing a range asks for its start and end. Existing ranges stay committed until both new bounds are valid. Back abandons the pending add/edit and returns to the unchanged summary. Removing the final range asks for a new start and disables confirmation. Input and editor actions cannot contact the source or create an operation. Each range produces a separate output file in the listed order, without merging or sorting overlapping ranges. If saved quality is `ask`, confirm opens a fixed height-limit menu without creating an operation or contacting the source. The choices match the per-download picker above. Choosing a height leaves saved `ask` unchanged. All clip ranges and the reply destination stay attached to the original draft, and the other saved settings resolve at admission. Before selection, edit, cancel and replacement remain available. Changing saved quality after opening the chooser does not bypass it. Bare `/cancel`, `cancel` and `отмена` cancel a pending draft. `/cancel UUID` still cancels a media operation. Bare `/cut` resumes the persisted state, including after a lost prompt or process restart. Other commands are not interpreted as time input. Unlike legacy `/cut URL`, this does not open source-aware format discovery or the combined audio/action menu. Conversation messages are retained rather than deleted. Prompts and errors do not echo source URLs.

Migration v6 introduced one draft per actor, bot and private chat. Migration v10 adds durable clip quality selection while preserving existing drafts. Repeated or older message IDs cannot advance a newer draft. Session IDs and revisions reject old buttons after edits, cancellation or replacement. Cancellation retains a tombstone so replay cannot resurrect the draft. Drafts have no automatic expiry and stay until cancellation or replacement. Migration v13 persists the committed range list and pending edit index. It preserves v12 singleton drafts, partial input, terminal states, quality links and confirmation identity. Older binaries reject the v13 schema, so rollback requires a compatible binary or restoration of a pre-migration backup. Every service action rechecks current identity authorization, and callbacks additionally require an accessible message from this bot in the caller's private chat.

Confirmation with a concrete saved quality, or selection from the height menu, first persists an immutable `Confirming` state. From then on, edit, cancel and replacement cannot discard an admission whose outcome is uncertain. The normal preferred-settings admission path uses a stable session key rather than the callback delivery ID. A retry after a crash between admission and recording its result finds the original operation and frozen settings. Failed admission leaves a retryable confirmation. Correct invalid saved preferences through `/settings`, then confirm again. Once admitted, use `/job UUID` or `/cancel UUID` for the operation. Repeated confirmation cannot restart delivery. For a chosen height, recovery exposes only that same choice. Ordinary `/cut` drafts remain independent of unrelated `/quality` choices. A draft transferred by Cut is linked to its original chooser, which can only resume that editor.

`just test-media cut-segments` exercises the multi-range editor, ordered real outputs, pending-edit recovery, revision fencing and confirmation/cache replay. `just test-media cut-quality` exercises the combined clip/height workflow. `just test-media cut` retains coverage of the original concrete-quality flow.

## Clearing your cache

Owner-private `/uncache URL` removes cached file-ID batches for the exact canonical source URL, across media modes, clip ranges, formats and credential versions, only within the sender's actor/current-bot partition. URL parsing follows the stored request representation. Query strings and fragments remain part of the match. Legacy `/uncache` uses an explicit minimum admin policy; this native configured-owner gate is intentionally unchanged. The command rejects missing/extra arguments, non-HTTP(S) URLs, embedded credentials and oversized input. It does not require valid saved format preferences, echo the URL, create a download, or delete Telegram files.

Other actors and bots, other URLs, imported legacy cache, credentials, settings, operation history and delivery receipts remain unchanged. This actor-only behavior was selected explicitly instead of copying legacy `/uncache`'s shared administrative scope. `/reload_cache` is not exposed, because the legacy handler only acknowledges a reload without performing one.

Clear and a per-actor/bot message watermark commit in one transaction. Repeated or older command messages do not delete entries that have since been recreated, even after restart or when the replay changes the URL. A fresh message can clear again. Ban and role checks apply before and at the mutation boundary. Groups and non-owner private senders cannot invoke the command. Migration v7 adds the durable watermark, so rollback needs a v7-compatible binary or a pre-migration backup.

Clearing affects subsequent cache lookups, not active work. A job may already hold a cached batch, and a running download may publish a new entry after the clear. The command neither cancels those jobs nor changes the replay of a completed operation. Downloading the URL again with a new message after a clear uploads fresh output when no active job has repopulated the cache.

## Personal cookie controls

Authorized actor-private `/cookie` lists personal records marked valid in pages of ten, reading only metadata. `/cookie DOMAIN` returns a record count or a missing/invalid status, never cookie values. Domains use strict bare-hostname syntax, case-insensitive with surrounding dots removed. A bare domain only inspects status, without fetching it or expanding provider aliases or subdomain wildcards. Malformed imported domains render as a fixed invalid-entry label, without echoing their text. Status reads cap content at 512 KiB and recognize Netscape HttpOnly records. Invalidated, malformed, oversized or canonically ambiguous imported records are reported as invalid rather than missing or a partial count.

`/cookie del DOMAIN` removes matching personal records. `/cookie clear` removes all of the sender's personal records, including invalid ones. Both preserve other users' cookies and every global-pool record, including pool records owned by the sender. They do not change preferences, jobs, delivery receipts or cache rows. Invalid saved format preferences do not block cookie controls. Groups, pending users and banned users remain outside this command boundary.

Deletion and a per-user Telegram message watermark commit in one transaction, with fresh authorization at the mutation boundary. A repeated or older command cannot remove cookies stored since the original command, even after restart or when the replay changes its arguments. A deletion that matches nothing still advances the watermark. Migration v8 adds this ledger. Rollback requires a compatible binary or a pre-migration backup.

A document captioned `/cookie DOMAIN` replaces that domain's personal cookie file. Bare `/cookie` on a document derives the domain from the filename stem, for example `youtube.com.txt`. Explicit domains take precedence. Foreign-bot commands, unrelated captions and group documents are ignored. Domain parsing stays strict, and document captions never enter the media or clip command parser.

The adapter checks authorization and the mutation watermark before calling Telegram `getFile`. For cloud Bot API it fetches only a validated relative path from the configured origin and refuses redirects. Local Bot API absolute paths require the explicit root mapping described below. Both paths enforce a 512 KiB file limit without creating temporary files. Attachment metadata, `getFile` size, response length and actual streamed bytes are checked independently. Files must contain strict UTF-8 Netscape text with at least one valid record. File contents, names, IDs and download URLs never appear in replies or logs. `YOINK_RUST_TELEGRAM_COOKIE_UPLOAD_TIMEOUT_SECS` bounds the complete `getFile` and body download, defaulting to 30 seconds. A failed fetch or invalid file leaves stored cookies and the watermark unchanged.

The existing Compose deployment uses TDLight local mode. Enable local document reads by setting `YOINK_RUST_BOT_API_FILE_ROOT` to the remote directory prefix, `YOINK_RUST_TELEGRAM_LOCAL_FILE_ROOT` to its read-only mount inside the Rust container, and `YOINK_RUST_BOT_API_URL` to the local API origin. Prefer mounting only this bot's document directory. Neither root may be `/` or contain traversal components. Absolute paths outside the configured prefix, symlinks at any traversed component and non-regular files are rejected. Reads use directory file descriptors and `openat` with `NOFOLLOW`, not a check-then-open pathname. Blocking filesystem work runs in a dedicated thread, with one shared read slot per adapter configuration. Cancellation retains that slot until the underlying read exits, so repeated timeouts cannot accumulate blocking workers. The response deadline cannot interrupt kernel filesystem I/O. Use a local disk mount, not a network or FUSE filesystem. A stuck mount may require operator recovery. Its outstanding read does not hold up Tokio runtime shutdown. This feature does not add or change a production mount. Without the paired configuration, absolute file paths are rejected.

Successful replacement rechecks authorization and advances the same per-user watermark as deletion in an Immediate transaction. It removes matching canonical-domain personal aliases and inserts one valid record with a fresh ID. Even reuploading identical bytes invalidates the old reference. Old uploads cannot overwrite a newer replacement or resurrect cookies after deletion, including after restart. Other personal domains and the global pool remain unchanged. A failed acknowledgement does not undo a committed replacement. Check `/cookie DOMAIN` or resend with a fresh message if the result is uncertain.

Removing or replacing a selected cookie invalidates its frozen reference. Queued execution and delivery rechecks fail rather than switching an existing job to another personal cookie or the global pool. An already running worker may finish its network requests. A new admission can select a permitted pool cookie through the existing resolver. Browser tokens, web management and pool administration are not implemented by these commands. The native `just test-media cookie-uploads` scenario exercises document ingestion separately from `just test-media cookies`, which covers listing and deletion.

Replacement enforces per-user domain and byte limits plus a global personal-cookie byte limit in the same transaction as fresh authorization and the replay watermark. All stored personal rows consume capacity, including malformed imported domains, invalid bodies and multibyte UTF-8 text. Global-pool rows do not consume personal capacity. Delete and clear remain available above lowered limits. Defaults are 128 domains per user, 64 MiB per user and 1 GiB globally. Configure `YOINK_RUST_PERSONAL_COOKIE_DOMAINS`, `YOINK_RUST_PERSONAL_COOKIE_ACTOR_BYTES` and `YOINK_RUST_PERSONAL_COOKIE_GLOBAL_BYTES`.

## Personal cookie URL import

Authorized actor-private `/cookie URL [DOMAIN]` fetches an HTTP(S) Netscape cookie file. An explicit domain uses the same strict canonicalization as document uploads. Without it, the domain comes from the original URL's host using the legacy `www.` and provider-alias normalization. Redirect hosts and file names do not choose the storage domain. Source URLs cannot contain credentials, fragments, whitespace or control characters. Arguments and source lengths are bounded, and URLs, query tokens and file contents stay out of replies and diagnostics.

The adapter checks authorization and the shared cookie mutation watermark before fetching. It uses a separate direct client without ambient proxies, saved credentials, cookies or a Referer header. All resolved addresses must be public and are pinned for the connection. Each of at most five redirects goes through the same validation, and HTTPS-to-HTTP redirects are rejected. No browser execution, archive extraction, custom request headers or authentication forwarding is supported.

Responses are limited to 512 KiB of strict UTF-8. Oversized declared lengths or streamed bodies, invalid Netscape text, unsupported response encodings and failed HTTP requests leave cookies and the watermark unchanged. `YOINK_RUST_COOKIE_IMPORT_TIMEOUT_SECS` covers concurrency wait, DNS, redirects and the complete body. The HTTP fetch and blocking DNS resolver each have four shared slots. A timed-out DNS caller does not release its resolver slot until the underlying lookup returns, and stuck resolver threads do not block runtime shutdown. Cookie persistence happens outside the transport deadline so the deadline cannot interrupt a commit. Successful imports use the existing personal-cookie replacement transaction, including fresh authorization, a new row ID and the common watermark shared with document upload, delete and clear. A delayed response cannot overwrite a newer cookie mutation. Replaying an old import after restart cannot refetch or resurrect a removed cookie.

Public-address checks are the default. `YOINK_RUST_COOKIE_IMPORT_PRIVATE_ORIGINS` explicitly permits exact literal-IP origins when an operator needs a trusted internal source. It has no effect on other origins, ports, DNS hostnames or the media worker's policy. The native fixture opts in only to its isolated local HTTP origin. This exception can expose paths on that endpoint to authorized users, so leave it empty for production unless needed. HTTP source URLs transfer the cookie file in plaintext. Prefer HTTPS or document upload.

`just test-media cookie-urls` exercises the native Bot API adapter with actual HTTP responses and cookie-authenticated media delivery. It checks the 512 KiB boundary, invalid bodies/encodings, private redirects and loops, authorization changes during fetch, a newer mutation overtaking a delayed response, and document/delete/clear replay across restart. The fixture restores cookies, user fields, settings and mutation watermarks. Rust regressions cover public/special/mixed DNS answers, redirect parsing and downgrade rejection, exact origin exceptions, and resolver capacity after caller cancellation. External providers and DNS rebinding against live infrastructure are not exercised. No schema migration is added, and global-pool records remain separate.

## Proxy usage

Authorized actor-private `/proxy` shows whether proxy use is enabled and offers an explicit enable or disable button. It accepts no arguments and does not expose, accept or replace proxy credentials. A valid personal proxy takes precedence over the configured system proxy. Either can enable the menu, unlike the legacy system-only guard. Worker origin restrictions still apply. Missing or malformed configuration cannot be enabled. Disabling remains available when configuration or unrelated saved format preferences are corrupt.

Buttons require the sender's own private chat and an accessible message from the current bot. Every action checks current authorization, and mutation rechecks bans and the saved settings revision. An old button cannot undo a newer choice, including after restart. Proxy changes share the `updated_at` revision with the settings editor, so edits in either menu can make the other's buttons stale. Reopen `/proxy` to read current state after a rejected button or failed Telegram edit. No schema migration or media operation is created. The generic `/settings` editor does not expose proxy toggles.

A toggle affects subsequent admissions, not the frozen route of an existing operation. Execution and delivery reject a frozen direct route when proxy use becomes enabled, and reject a frozen proxy route when it becomes disabled. They do not silently reroute or deliver results under a different network policy. A worker already running may finish its network requests, but the delivery recheck prevents sending invalidated results. Resubmit the download with a new message under the intended policy.

## Saved settings and overrides

Authorized actor-private `/settings` and `/format` open the same EN/RU editor for `quality`, `codec`, `container`, `audio_codec`, `send_as_file`, `gallery_zip`, `subs_lang`, `subs_auto` and `nsfw_blur`. `/settings FIELD VALUE` and `/format FIELD VALUE` also accept explicit values. Values are closed choices shown by the buttons, except subtitle language, which accepts a valid exact tag up to the imported column's eight-character limit. Quality also accepts `ask` for the private per-download picker. Unknown fields, raw arguments, proxy URLs, credentials and embedding are not writable through this editor. It deliberately replaces the legacy `/settings` buttons that merely suggested other commands, rather than advertising unavailable features.

Buttons require an accessible message from this bot in the caller's private chat. Each mutation rechecks identity and global bans. The SQL upsert changes only the selected field and its timestamp, and creates default preferences only for an existing authorized user. Mutation buttons carry the settings `updated_at` revision. Writes compare it atomically and advance it monotonically. A stale button or replay after another choice cannot overwrite that choice and tells the user to reopen `/settings`. Text commands set absolute values without a revision precondition. No new schema or media operation is needed. A failed Telegram reply/edit does not undo a committed setting. Reopening `/settings` reads the current persisted values. Groups, user registration and other legacy configuration workflows remain outside this editor.

Saved video settings apply quality, video codec, container and file delivery. Audio mode applies audio codec and file delivery, ignoring video-only settings. Image mode applies ZIP and file-delivery preferences. Subtitle mode applies only `subs_lang` and `subs_auto`. An explicit `/subs` works even when the embedding preference `subs_enabled` is false. Subtitle preferences do not affect other media modes. Keyboard and raw `args_json` settings are not forwarded to the worker. Cookie/proxy authorization remains separate and is still checked.

Explicit flags are mode-specific:

| Flag | Values | Modes |
| --- | --- | --- |
| `--height` | `best` or integer 1–100000 | Video, playlist, cut |
| `--video-codec` | `h264`, `h265`, `av1`, `vp9`, `any` | Video, playlist, cut |
| `--audio-codec` | `best`, `aac`, `mp3`, `opus` | Video, audio, playlist, cut |
| `--container` | `mp4`, `mkv`, `webm` | Video, playlist, cut |
| `--send-as-file` | `true`, `false` | Video, audio, image, playlist, cut |
| `--gallery-zip` | `true`, `false` | Image only |
| `--subtitle-language` | Exact language tag, such as `en`, `ru`, `zh-Hans` | Subs only |
| `--subtitle-auto` | `true`, `false` | Subs only |

Absent flags inherit relevant saved settings. Explicit `best` and `false` override saved values rather than meaning “inherit”. Duplicate, unknown, missing-value and mode-inappropriate flags are rejected. WebM requires VP9/AV1 video and explicit Opus audio. Stored `ask` opens the private per-download picker for ready Telegram video requests. Explicit `--height` supplies a concrete choice or `best` without prompting. Groups and direct HTTP admission still require a concrete quality. Stored audio preferences do not change video audio encoding unless an explicit `--audio-codec` is supplied.

For example, `/video --height best --send-as-file false URL` overrides a saved height limit and document delivery. `/audio --audio-codec aac URL` overrides the saved audio codec. Settings changes after admission do not alter queued processing, cache identity or same-message replay. Changing flags or other request intent under the same message ID is a conflict, not a second operation. Replay still requires current access authorization. Execution and delivery also revalidate network credentials.

Subtitle language tags contain two or three lowercase ASCII letters and at most one two-to-eight-character alphanumeric suffix. Regexes, comma lists and wildcard selection are not accepted. Track selection keeps the legacy `en`-only rule, while other languages also request their exact `-orig` track. Manual tracks take priority, and automatic tracks are eligible only when enabled. Outputs prefer SRT, then VTT, then ASS, then SSA. Other formats are rejected rather than returned through an unrestricted `best` fallback. All files must contain valid UTF-8 timing cues. ASS/SSA require a first-line `[Script Info]` header, an `[Events]` section, a declared field layout and nonempty dialogue with valid increasing start/end times. UTF-8 BOMs, CRLF, style sections, comments, comma-containing dialogue and ordinary override tags are retained. The worker validates these files as text and never renders their tags, loads fonts or converts them. ASS/SSA documents use `text/x-ssa` with their original `.ass` or `.ssa` extension. The executor checks the header signature and bounded filename separately. At most two files are returned, each bounded by both the configured artifact limit and a 4 MiB text ceiling. The aggregate byte/item budgets still apply. Unsupported formats, absent tracks or any failed track abort before delivery. Existing non-subtitle serialized requests and cache identities remain unchanged. Older binaries cannot decode stored subtitle jobs. Keep runtime and worker revisions matched, and verify rollback compatibility separately.

## Group and topic boundary

Groups stay disabled by default. Opting in does not create users or groups, change roles, or open private credential/admin controls to non-owners. Identity records must already exist. Admins can create and enable groups, configure topics and manage local member overrides through `/api/v1/groups`; automatic Telegram registration is not implemented. Bot senders, anonymous `sender_chat` messages and channel posts are ignored. `/status` remains owner-private. Unauthorized group commands are silent and create no operation.

Global bans take precedence over local grants. Group enablement and topic rules apply even to the owner. An explicit group role override wins over an auto-grant. Auto-grants can elevate the effective group role without writing the global user role. Authorization is read again before execution, delivery and progress edits. Disabling groups also blocks persisted group jobs from starting after restart.

The admission reply, individual uploads, albums and cached sends retain the source chat and topic. There is no fallback into the actor's private chat or the group's General topic. A media receipt naming another topic is unconfirmed and becomes `delivery_unknown`, with no automatic resend. `/job` and `/cancel` from another topic cannot expose or change the operation, even for its original actor. Reply-message IDs may differ on subsequent commands, but the actor, bot, chat and topic must match.

## Progress-message lifecycle

Migration v5 adds one progress notice per operation. The first confirmed admission-reply message ID wins, including command replay. Startup resumes edits of known messages only. An initial `sendMessage` whose acknowledgement is lost, or a crash before its ID is persisted, cannot be retried without risking duplicate messages. That operation remains accessible through `/job`; no replacement status message is sent automatically.

Each configured tick processes one due notice, rechecks current authorization and destination, and renders the latest operation state. Unchanged text does not issue an API request. Completed, failed, cancelled, partial and uncertain deliveries stop after an acknowledged final edit. Partial and uncertain outcomes warn against blindly resubmitting. Counts describe confirmed receipts, not proof that an unacknowledged file was never received.

Edits have a bounded deadline. Network ambiguity and unknown API failures retry the same known message. Telegram `message is not modified` counts as acknowledgement, covering a lost response followed by restart. `retry_after` is persisted, with a maximum supported delay of one day; larger delays retire the notice rather than retrying too soon. Deleted/inaccessible messages and revoked access also retire the notice without creating another message. None of these edit retries can restart media delivery. The existing no-retry rule for ambiguous media sends is unchanged.

## Versioned automatic provider routing

New automatic requests freeze routing table v1 in Rust at admission, across native
adapters. Exact canonical host labels/subdomains match YouTube-only first, then
`2ch.su`, `4chan.org`, `e-hentai.org`, `e621.net`, `gelbooru.com`, `kemono.cr`,
`kemono.party`, `coomer.party`, `nhentai.net`, `civitai.com`, `wallhaven.cc` as
gallery-first; VK hosts with literal `/wall-` or `/album-` path prefixes next;
Instagram hosts next as yt-dlp then gallery; otherwise yt-dlp. Query strings and
embedded domain/path text cannot select another provider. Explicit engine intent is
preserved, and explicit image uses gallery independently of the automatic domain
table. Format reports and subtitles remain yt-dlp-only.

The serialized typed engines `auto_yt_dlp_v1`, `auto_gallery_v1` and
`auto_fallback_v1` distinguish resolved automatic intent from explicit providers and
include the table version in cache identity. Replay compares original automatic
intent, retains the first frozen snapshot and does not re-resolve credentials or
preferences. Older stored `auto` requests keep their previous behavior. New-version
automatic requests deliberately miss older cache identities. No SQL or schema
migration is added, and released migrations 1–16 are unchanged.

Gallery no longer refuses ordinary video requests or silently filters video out of
mixed galleries. Finalized artifacts retain extractor order, share bounded batch
ordinals across child extractors, and pass the existing native delivery and NSFW
checks. Fallback uses isolated provider workspaces and separate metadata collectors;
failed primary files/prose cannot become fallback outputs or cache entries. The
legacy broad-exception fallback is intentionally narrowed: confinement/network
policy, budget, cancellation and local processing failures never trigger another
provider. Gallery writes are confined before opening a destination.

Fallback authority is default-deny. Only recognized expected extractor/HTTP/download
errors in the actual yt-dlp phase enable another provider. Source validation,
configuration/tool/cookie setup, metadata/progress callbacks, unexpected local errors
and postprocessing never acquire provider authority. Network-policy errors carry
structural markers; a monotonic guard/relay fault counter preserves denial when a
library or relay discards the original exception. The pinned downloader's typed
retry cause is retained without changing its retries or extraction implementation.
Diagnostic text cannot grant fallback eligibility.

Verification: deterministic Rust routing/deceptive-host/VK-query and native storage
